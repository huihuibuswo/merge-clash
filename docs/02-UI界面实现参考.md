# Merge Clash UI 界面实现参考

## 1. 文档目标

本文基于 [`nextlevelbuilder/ui-ux-pro-max-skill`](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill.git) 对应的本地 `ui-ux-pro-max` skill，为 Merge Clash 提供可直接指导 Vue 3 + TypeScript + Naive UI 实现的界面规范。

设计目标：让用户在高密度桌面界面中稳定完成“选择模板 -> 添加并测试订阅 -> 合并 -> 编辑分组 -> 校验 -> 发布”的工作流，并能快速识别失败阶段、草稿状态和发布状态。

设计系统的单一事实来源：[MASTER.md](../design-system/merge-clash/MASTER.md)。本文描述页面结构和交互；颜色、字体、间距、圆角、图标和动效以 Master 为准。

## 2. 产品体验原则

- 首屏直接进入工作台，不制作营销首页。
- 高频动作靠近数据，高风险动作远离主操作。
- 所有敏感数据默认脱敏。
- 用户始终知道当前查看的是草稿还是已发布版本。
- 网络任务展示阶段，不只显示一个无限旋转图标。
- 可视化表单生成配置，YAML 预览只读。
- 动态 provider 和静态节点模式必须在模板选择区明确区分。

## 3. 应用壳层

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Merge Clash       当前项目 ▾     草稿未发布          服务：运行中   ─ □ × │ 52
├──────────────┬───────────────────────────────────────────────────────────┤
│ 概览         │ 页面标题                         次要操作   [主要操作]    │ 44
│ 配置模板     ├───────────────────────────────────────────────────────────┤
│ 订阅源       │                                                           │
│ 节点与分组   │                       页面内容                            │
│ 配置预览     │                                                           │
│ 本地发布     │                                                           │
│              │                                                           │
│ 设置         │                                                           │
└──────────────┴───────────────────────────────────────────────────────────┘
     216px
```

- 使用 `NLayout`、`NLayoutSider`、`NLayoutHeader`、`NLayoutContent`。
- 侧栏导航使用图标加文字，不使用图标独立导航。
- 页面工具栏固定在内容顶部，但必须为内容预留 44px。
- 标题栏显示项目、草稿状态和局域网服务状态；不显示冗长功能说明。
- Windows 窗口控制区与 Tauri 自定义拖拽区不得覆盖交互控件。

## 4. 导航与页面状态

| 页面 | 主操作 | 常驻状态 |
|---|---|---|
| 概览 | 刷新全部 | 最近刷新、草稿、发布、服务状态 |
| 配置模板 | 使用此模板 / 重新生成草稿 | 当前模板、版本、合并模式 |
| 订阅源 | 添加订阅 | 启用数、失败数、刷新进度 |
| 节点与分组 | 保存分组 | 节点数、组数、未保存修改 |
| 配置预览 | 发布当前草稿 | 阻断、警告、哈希、版本差异 |
| 本地发布 | 启动服务 / 停止服务 | 地址、端口、访问时间 |
| 设置 | 保存设置 | 主题、数据目录、日志级别 |

路由切换保留表格筛选、排序、分页和滚动位置。页面存在未保存更改时，离开前确认。

## 5. 概览页

```text
┌─运行状态───────────────────────────────────────────────────────────────┐
│ 模板 Clash Verge Rev v1 │ 订阅 4/5 成功 │ 节点 186 │ 草稿未发布        │
└────────────────────────────────────────────────────────────────────────┘
┌─需要处理───────────────────────────────────────────────────────────────┐
│ [错误] 订阅 B TLS 连接失败                         [重试] [编辑]        │
│ [警告] 动态模式发现 2 个跨 Provider 同名节点       [查看冲突]           │
└────────────────────────────────────────────────────────────────────────┘
┌─本地发布───────────────────────────────────────────────────────────────┐
│ 运行中  192.168.1.20:17890  最后访问 14:31       [复制地址] [打开详情] │
└────────────────────────────────────────────────────────────────────────┘
```

- 不使用四个大型 KPI 卡片；摘要放在一条紧凑状态带中。
- “需要处理”仅展示阻断项和高价值警告，最多 5 条。
- 无问题时显示简洁成功状态和最近操作，不添加装饰插图。

Naive UI：`NDescriptions`、`NAlert`、`NButton`、`NTag`、`NSkeleton`。

## 6. 配置模板页

模板作为可重复选择项，可以使用边框列表或紧凑卡片，圆角不超过 6px。

```text
┌─模板列表──────────────────────┬─模板详情───────────────────────────────┐
│ ● Clash Verge Rev             │ Clash Verge Rev v1                    │
│   Mihomo / 动态+静态          │ 默认合并模式 [动态 Provider|静态节点] │
│ ○ FlClash                     │                                       │
│   Mihomo / 动态+静态          │ 代理组：节点选择、发达地区、美国自动  │
│ ○ Mihomo 通用                 │ 外部依赖：MetaCubeX cn.mrs            │
│                               │                                       │
│                               │              [预览生成结果] [使用模板]│
└───────────────────────────────┴───────────────────────────────────────┘
```

- 模板选择使用单选语义，合并模式使用 `NSegmented`。
- 外部规则地址只显示域名和用途，完整地址通过安全详情查看。
- 切换模板或模式会重建草稿，必须明确展示将受影响的内容。
- 当前模板项显示 `当前使用` 文本，不只依赖边框颜色。

Naive UI：`NRadioGroup`、`NSegmented`、`NDescriptions`、`NCollapse`、`NAlert`。

## 7. 订阅源页

### 7.1 表格

| 列 | 宽度/行为 |
|---|---|
| 选择 | 40px，批量启停/刷新 |
| 状态 | 88px，图标加文本 |
| 名称 | min 140px，可排序 |
| 订阅地址 | min 220px，固定脱敏，单行省略 |
| 节点 | 72px，tabular-nums |
| 最近成功 | 140px，本地化时间 |
| 耗时 | 80px，tabular-nums |
| 操作 | 132px，粘性右列 |

- 表头下方提供搜索、状态筛选和“仅显示异常”。
- 50 条以上启用虚拟滚动；批量操作栏占据固定高度，避免布局跳动。
- 行操作优先使用图标按钮：测试、刷新、编辑、更多；均带 tooltip。
- 删除放入更多菜单并二次确认。

### 7.2 新增订阅弹窗

```text
名称       [____________________________]
订阅 URL   [•••••••••••••••••••••• 👁]
           完整地址仅用于请求，日志始终脱敏

连接测试
✓ URL 格式     ✓ TLS/HTTP 200     ✓ YAML     ✓ 识别 42 个节点
耗时 684ms                                      [重新测试]

                                  [取消] [保存订阅]
```

- URL 在未测试时也可保存，但显示警告；推荐流程是测试通过后保存。
- 测试步骤固定占位，状态变化不改变弹窗宽高。
- 测试失败显示失败阶段、原因和恢复动作，例如“证书验证失败，检查系统时间或订阅地址”。
- `保存订阅` 不等于拉取全部，不触发无关任务。

Naive UI：`NModal`、`NForm`、`NInput`、`NSteps`、`NProgress`、`NAlert`。

## 8. 节点与分组页

这是主要工作区，宽屏采用三栏固定轨道：

```text
┌─节点库 300px────────┬─代理组 260px──────┬─组编辑器 minmax(420px,1fr)─────┐
│ 搜索 [___________]  │ 节点选择      186 │ 名称 [节点选择]  类型 [select]│
│ 来源 [全部] 类型[...]│ 发达地区自动   42 │ 成员                              │
│ □ 节点 A            │ 美国自动       18 │ 1 发达地区自动        ↑ ↓ ×      │
│ □ 节点 B            │ DIRECT          - │ 2 美国自动            ↑ ↓ ×      │
│ □ 节点 C            │                     │ 3 DIRECT              ↑ ↓ ×      │
│ ...                 │ [+ 新建代理组]     │                                   │
│ [加入当前组]         │                     │ [恢复模板值]       [保存分组]    │
└─────────────────────┴─────────────────────┴───────────────────────────────────┘
```

- 三栏尺寸使用 CSS Grid 稳定约束，加载、错误或 tooltip 不得改变列宽。
- 左栏节点支持来源、协议、名称和地区标签筛选，多选后批量加入。
- 中栏显示代理组类型、成员数和错误标记，可拖拽排序。
- 右栏按组类型渐进展示参数；`select` 不显示健康检查字段。
- 拖拽同时提供上移/下移按钮和键盘菜单。
- 不在卡片中再嵌套卡片，三栏使用连续面板和分隔线。

### 8.1 地区筛选编辑

- `简单`/`高级`使用 `NSegmented`。
- 简单模式选择国家/地区标签和排除预设。
- 高级模式编辑 `filter`、`exclude-filter`，输入使用等宽字体。
- 右侧或下方实时显示“命中 42、排除 7、未匹配 137”，并提供节点列表抽屉。
- 正则错误在字段下方展示，不等到发布时才反馈。

Naive UI：`NDataTable`、`NTree` 或虚拟列表、`NCheckbox`、`NSelect`、`NSegmented`、`NInput`、`NDrawer`、`NDropdown`。

## 9. 配置预览页

```text
┌ 阻断 0 │ 警告 2 │ 节点 186 │ 代理组 4 │ 规则 24 │ SHA-256 ab12… ┐
├───────────────────────────────────────────────────────────────────────┤
│ [校验问题] [版本差异] [YAML 预览]                                    │
│                                                                       │
│ Warning  动态模式包含原始订阅 URL                  [查看影响]          │
│ Warning  外部规则 cn.mrs 当前无法测试               [重试]             │
│                                                                       │
│                                             [导出 YAML] [发布当前草稿] │
└───────────────────────────────────────────────────────────────────────┘
```

- 标签页使用 `NTabs`，不同时并排展示三份复杂内容。
- YAML 预览只读、等宽字体、带行号和搜索；大文件延迟加载。
- 校验问题按阻断、警告、信息排序，每条包含对象、原因和解决动作。
- 发布按钮在存在阻断项时禁用，并在按钮附近说明原因。
- 版本差异优先展示结构化摘要，不默认渲染整份文本 diff。

## 10. 本地发布页

```text
服务状态  ● 运行中                 [停止服务]
监听地址  0.0.0.0     端口 [17890]

手机订阅地址
[http://192.168.1.20:17890/subscription/••••/config.yaml] [复制]
[二维码]  专用网络可访问；公用网络不建议开启

最近访问
14:31  192.168.1.55  200  12.4 KiB

危险操作                                             [重置访问令牌]
```

- 服务状态使用文本、图标和颜色三重表达。
- 复制成功给出短 Toast，不能永久改变按钮宽度。
- 二维码保持固定正方形尺寸并预留加载占位。
- 重置令牌独立放在危险操作区，需要确认旧 URL 将立即失效。
- 防火墙错误提供“重试检测”和系统设置指引，不直接宣称应用可自动修复。

Naive UI：`NForm`、`NInputNumber`、`NCode`、`NAlert`、`NPopconfirm`、`NDataTable`。

## 11. 设置页

设置按全宽分区排列，不用嵌套卡片：

- 外观：跟随系统/浅色/深色，紧凑密度开关。
- 网络：超时、响应大小上限、User-Agent；高级项默认折叠。
- 数据：数据目录只读展示、导出诊断信息、清理历史快照。
- 日志：日志级别和打开日志目录；明确日志已脱敏。

危险操作固定在页面底部，并与普通设置保持至少 32px 间距。

## 12. 全局状态规范

| 状态 | 页面表现 |
|---|---|
| 初次加载 <300ms | 保持原布局，不闪 spinner |
| 加载 >300ms | 局部 skeleton 或步骤进度 |
| 空数据 | 说明原因并提供唯一主操作 |
| 网络超时 | 显示阶段、耗时、重试和编辑地址 |
| 部分成功 | 保留成功结果，列出失败来源，不使用全局失败页 |
| 草稿脏数据 | 顶栏显示“未保存”或“未发布”，离开前确认 |
| 发布成功 | 更新版本、哈希和时间，Toast 简短确认 |
| 服务失败 | 桌面编辑保持可用，本地发布入口显示阻断状态 |

## 13. Naive UI 主题与组件约束

- 在根组件通过 `NConfigProvider` 注入 light/dark theme overrides。
- 颜色只映射语义 token，不在页面 SFC 中散落十六进制值。
- 使用 `NMessageProvider`、`NDialogProvider`、`NNotificationProvider` 统一反馈。
- 表单规则集中定义 TypeScript 类型，前端校验只改善体验，Rust 仍执行最终校验。
- 大型 YAML 和节点集合使用 `shallowRef`，筛选输入 150-250ms debounce。
- 页面级功能按路由懒加载；不引入 GSAP、低代码表单引擎或第二套 UI 库。

建议组件密度：

| 组件 | 建议 |
|---|---|
| Button/Input/Select | 常规 34px，工具栏 30px |
| DataTable | 表头 36px，数据行 40px |
| Modal | 520-640px；复杂编辑使用 Drawer 或页面 |
| Drawer | 节点匹配详情 480-560px |
| Tag | 只用于短状态，不承载长说明 |
| Card | 仅模板重复项使用，圆角 6px |

## 14. 可访问性验收

- 键盘可完成完整主流程，Tab 顺序与视觉顺序一致。
- 每个图标按钮具备 tooltip 和 `aria-label`。
- 页面路由切换后聚焦主标题，弹窗关闭后焦点回到触发按钮。
- 表格排序使用 `aria-sort`，错误使用 `role="alert"`。
- 红、绿、黄状态均附加图标和文本。
- 200% 文本缩放下按钮文本不溢出、表单标签不遮挡输入。
- `prefers-reduced-motion` 下关闭非必要过渡。
- 浅色与深色主题分别验证 4.5:1 正文对比度。

## 15. 视觉与交互验收尺寸

必须检查：

- 960x640：最小窗口，侧栏折叠，关键操作可达。
- 1280x800：默认窗口，三栏分组编辑器完整显示。
- 1440x900：宽屏信息密度合理，不出现过宽文本区。
- 1920x1080：内容可适度扩展，但 YAML 行宽和表单宽度受控。

截图验收重点：无文本截断误导、无组件重叠、无卡片嵌套、无布局跳动、深浅主题状态一致。

## 17. 明确不做

- 不做营销落地页或新手引导轮播。
- 不用 emoji、渐变球、玻璃拟态、3D 或装饰插画。
- 不把每个统计数字做成大型卡片。
- 不在 MVP 中实现自由拖拽画布或通用 YAML 双向编辑器。
- 不为了动画引入 GSAP。
- 不让前端 UI 成为配置合法性的最终裁判。
